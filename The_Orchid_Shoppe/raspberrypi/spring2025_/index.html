Deployment Notes

Serve this from the Pi with nginx or Apache on the management subnet only. Pair it with Basic Auth, firewall allow-listing, and HTTPS using your internal CA.

DNS Sinkhole Operations Dashboard

Built for your home cyber range: a cleaner management plane for Pi-hole, pfSense, ESXi, FortiGate, FortiSwitch, and jump resources. The page is designed to be static, fast, and safer than a gimmick dashboard: no embedded passwords, no fake client-side auth, and no hidden shortcut tricks.

Open Pi-hole Admin
This dashboard should not be your only security control. The page is safe by design, but the real protection comes from restricting network exposure, requiring web auth at the server, and keeping the Pi on the management subnet.

Hardening Checklist

The secure part is mostly server-side and network-side.

  • Restrict source IPs
    Allow only the management subnet or jump host to reach the dashboard.    Network
  • Enable web auth
    Use nginx Basic Auth or another server-side method.    Web
  • Use HTTPS
    Issue a cert from your internal CA and redirect HTTP to HTTPS.    TLS
  • Disable password SSH if possible
    Prefer keys and keep the service off the public side.    SSH
  • No secrets in HTML
    Do not hardcode usernames, tokens, or passwords into this page.    Design

Operations Notes

Quick commands for the Pi. Hidden by default so the page stays clean.

sudo pihole status pihole -t pihole -g ip a ss -tulpn sudo systemctl status pihole-FTL sudo systemctl status nginx sudo tail -f /var/log/pihole/pihole.log sudo journalctl -u pihole-FTL -n 50 --no-pager

Tip: keep this dashboard static and simple. Pulling live system data into the page is possible, but it adds attack surface and maintenance overhead.
